== Running the examples

Java 21 or newer. Compile everything once, then run whichever demo you want.

[source,bash]
----
cd java/multithreading
javac --release 21 -g -d out $(find examples -name '*.java')

java -cp out examples.basics.ThreadBasicsDemo
java -cp out examples.sharedstate.RaceConditionDemo
java -cp out examples.coordination.LockCoordinationDemo
java -cp out examples.executors.ExecutorDemo
java -cp out examples.virtualthreads.VirtualThreadDemo
----

Each demo has a `main`, prints numbered sections, and needs no arguments or dependencies.

The lost-update number in `RaceConditionDemo` is not fixed. The run quoted in these documents produced `104941`; another run can produce a different wrong number. That difference is part of the lesson.

All output quoted in the documents was produced by compiling with `javac --release 21` and running on the JDK available in this workspace.

== The shortest possible summary

Multithreading means one Java process has more than one path of execution. That lets a backend service keep doing useful work while other work waits for I/O, but it also means shared mutable objects need coordination.

The core rule is simple: if two threads can read and write the same mutable state, decide who is allowed to touch it, when other threads are allowed to see it, and how the whole operation is protected.

Prefer higher-level tools first: immutable data, request-scoped objects, concurrent collections, executors, virtual threads for blocking I/O, and structured ownership. Reach for low-level locks only when those tools do not express the operation.
