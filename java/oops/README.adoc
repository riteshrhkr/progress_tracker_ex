== Running the examples

Java 21 or newer. Compile everything once, then run whichever demo you want.

[source,bash]
----
cd java/oops
javac --release 21 -g -d out $(find examples -name '*.java')

java -cp out examples.basics.ClassObjectDemo
java -cp out examples.basics.ConstructorOrderDemo
java -cp out examples.pillars.EncapsulationDemo
java -cp out examples.pillars.InheritanceDemo
java -cp out examples.pillars.PolymorphismDemo
java -cp out examples.pillars.AbstractionDemo
java -cp out examples.contracts.EqualsHashCodeDemo
java -cp out examples.contracts.ImmutabilityDemo
java -cp out examples.design.CompositionDemo
java -cp out examples.design.SolidDemo
java -cp out examples.design.NestedClassDemo
----

Each demo has a `main`, prints numbered sections, and needs no arguments or dependencies.

`-g` keeps local variable names in the class files, which is what makes `NullPointerException` messages say `because "missing" is null` instead of `because "<local6>" is null`.

One of the warnings javac can emit is itself part of the lesson. Turn linting on to see it:

[source,bash]
----
javac --release 21 -Xlint:all -d out $(find examples -name '*.java')
----

----
warning: [overrides] Class BadUser overrides equals, but neither it nor any
superclass overrides hashCode method
----

That is javac catching the broken class in `EqualsHashCodeDemo` before it ever runs, which is a good argument for keeping `-Xlint:all` on in real builds. The other two warnings are incidental: `CompositionDemo` extends `ArrayList` and `HashSet` without declaring a `serialVersionUID`, which is exactly the kind of inherited obligation that document is arguing against.

All output quoted in the documents was produced by running these files on OpenJDK 26 with `--release 21`.

== The shortest possible summary

Data and the rules about that data belong in the same place, and everything else in this topic is machinery for keeping that true as the codebase grows.

A variable holds an address, never an object. Methods are chosen at runtime from the real object, while fields, static methods and overloads are chosen at compile time from the declared type — most of the surprises in Java OOP come from mixing those two rules up.

Beyond that, three habits prevent most of the damage: copy mutable objects at the class boundary, override `equals` and `hashCode` as one decision, and hold an object rather than extending its class unless substitution genuinely holds.
